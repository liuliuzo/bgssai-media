# 用户登录页整理（2026-09-26）

> 原型：`docs/demo-static/web/user/login-20260926.html`
> 详设：`docs/architecture/login-page-cleanup-20260926.md`
> 口径：骨架 `docs/BGSSAI-Standards.md` §14 登录页统一口径、§15 法务同意行与页脚

## 背景

登录卡片标题写「用户登录」，卡片里常驻一条「演示账号：用户名 demo，密码 user123」（开发者文字上了用户界面）；
登录方式写「密码登录」；每个输入框上方有字段标签、框里又写一遍同样的占位符；
发码按钮一直可点、没有倒计时，发码后表单下再多出一条「验证码已发送至邮箱 / 手机」；
验证码登录其实是登录即注册，主按钮却只写「登录」；「用 Chat 登录」没开通时弹的是后端给运维看的说明。
手机号输入框没有边框，和上下两个输入框对不齐。

## 需求

1. 卡片自上而下：品牌行（BGSSAI MEDIA）→ 装饰动效 → 标题「欢迎回来」→ 一排三个登录方式 `密码` / `邮箱验证码` / `手机验证码`（默认手机验证码）→ 表单 + 主按钮 → 第三方账号登录 → 一行法律同意。去掉演示账号提示。
2. 字段名只给读屏，输入框只显示占位符：`请输入用户名`、`请输入密码`、`请输入邮箱地址`、`6 位验证码`；手机号框与其它输入框同一套边框。
3. 密码主按钮「登录」；两种验证码主按钮「登录 / 注册」（验证码登录对未注册的邮箱 / 手机号自动建号）。
4. 发码按钮「获取验证码」，发出后显示「N 秒后重发」倒计时 60 秒；邮箱与手机各自一个倒计时，切换方式不互相影响；发码只弹一次「验证码已发送」，不再在表单下多挂一条提示。
5. 第三方区只画已开通渠道（微信 / 抖音 / 百度 / 支付宝 / 用 Chat 登录），一个都没有时整段（含分隔线）不出现；按钮不带悬停提示。
6. 「用 Chat 登录」未开通时只提示「该登录方式暂不可用，请换一种方式登录」。
7. BGSSAI BOT 下载是页面顶部常驻导航（`bot-download-entry.html`），卡片内不再另放。

## 验收

1. 1280 与 390 宽度下卡片内没有「用户登录」「演示账号」「密码登录」、没有输入框上方的字段标签。
2. 手机发码后切到邮箱验证码，邮箱的「获取验证码」可用；切回手机倒计时仍在走。
3. 全部渠道未开通时第三方区（含分隔线）不出现；全部开通时五个按钮品牌名都不折行。
